# UI review — local preview

Reviewed with the T3 browser against the running local preview. Reference: existing Base UI/shadcn components, Cnippet registry patterns, and the web-ui-accessibility skill. This is a bounded review of available screens and states, not a WCAG conformance evaluation.

## Changes

- Members and Invites now use the same centered content width and spacing as Settings.
- Side sheets use full phone width rather than a cramped three-quarter-width panel. Shared sheets are viewport-height bounded and scroll internally.
- Player controls fit on one row at 320px while retaining 44px targets.
- Video controls use the available card width on phones. Below 400px, cards stack their thumbnail and details so inline rename has usable space.

No new component or dependency was needed. Existing shadcn/Base UI primitives were reused. Sheet and Button documentation was retrieved with the shadcn CLI; the official Sheet and Base UI Dialog references were read.

## Executed checks

- Screenshots inspected: Projects, Settings, Members, Invites, project detail, video review, Share panel, upload sheet, guest name entry, drawing controls, and dark video review.
- Eight route states checked at 320, 390, 768 and 1280 CSS pixels: home, settings, members, invites, project detail, video review, already-member invite outcome, unavailable share outcome. All 32 checks had no horizontal overflow and no axe WCAG A/AA violations.
- Guest review also passed axe with no violations.
- Media screens produced incomplete contrast, video-caption, and checkbox naming checks. Playback controls have explicit accessible names; these incomplete results still require manual assistive-technology and media-content review.
- Uploaded a generated H.264 MP4 through the actual upload dialog; it appeared as a ready video. Its player reached readyState 4 with duration 1 second.
- Submitted a comment and verified it appeared in the list.
- Created a local invite and share link; entered the guest name and opened guest review.
- Opened inline rename and cancelled using Escape. At 320px the input width increased from 53px to 177px after the card fix; the status control moved 0px when opening rename.
- Verified all five player buttons share the same vertical coordinate at 320px after the control spacing fix.
- Typecheck, lint and diff whitespace checks pass.

## Scope limits

The preview automatically authenticates a test owner. Real Clerk sign-in, new-member invitation redemption, role-specific screens for other accounts, real Mux processing, external sharing delivery, destructive actions, network failure recovery, actual mobile hardware, screen readers, forced colors, reduced-motion behavior, 200% text and actual 400% browser zoom were not fully exercised. Drawing controls were opened; a complete drawn-comment round trip was not exercised. The screenshots and axe checks do not establish whole-product accessibility or usability.

SquirrelScan 0.0.43 ran offline against one local development page. Report: /tmp/cutnotes-ui-audit/squirrel.json. Overall 29/F, accessibility 93, 64 checks passed, 26 warnings, 5 failures. This HTTP scan sees the development app shell and reports SEO/security/crawlability findings; it does not inspect authenticated client UI or establish production quality. No comparable pre-change production-build baseline was collected. No production SEO/security changes were made based on this scan.
